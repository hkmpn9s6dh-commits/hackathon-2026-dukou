## 二、作品

**《渡口》Crossing at First Light**，4:12，Cinematic Single。

一个渡口在天亮前后摆四次渡：I 未亮 / II 微亮 / III 日出 / IV 对岸。
52 小节，52 BPM，D 多利亚；动机 D–F–A–G–E 落在 9 音上，不解决。

### 核心约束：单源作曲

**全曲没有一个采样、没有一个预置音色、没有一段外部音频。** 所有声音都由同一个 400 ms 的
模态合成钢板脉冲派生：

| 声音 | 怎么从钢板来 |
|---|---|
| 钟 / 锣 | 同一块板换基频再敲（模态比例不变，板越小响越短） |
| 水 | 板的噪声尾颗粒化 |
| 引擎 | 板低通到 140 Hz，循环成 3.3 s 冲程，按 7.6 Hz 点火调幅 |
| 弦垫 | 板的模态谱"冻结"成谐波列（频域放分音，三份微失谐） |
| 箫 | 第 k 次谐波取板谱里离 k·f 最近的模态幅度 |
| 房间 | 板自己的尾巴拉伸 + 谱相位随机化 + 拉平倾斜，就是混响 IR |

这条约束**机器可验证**：渲染时每条声部记一笔来源，验收断言"来源集合只有一个元素"。
实测 **209 次声部调用，来源集合 = `{steel_impulse@seed20261201}`**。

它服务的正是评委七项里的 "how the AI-assisted process serves the music"。

## 四、可复用的六条

1. **总线电平要按 K 加权响度对齐，不能按 RMS。** RMS 对齐会让低频总线在能量上压倒一切：
   第一版 93% 能量落在 120 Hz 以下、谱重心 106 Hz、LRA 只剩 1.1 LU（等于一条砖）。
2. **混响 IR 要按能量归一，不能按峰值。** 峰值归一会让湿声比干声高 12.5 dB，整首歌泡进泥里。
   判据：湿/干 LUFS 差 < 3 dB。
3. **频谱匹配做两遍。** 第一遍拉完会过冲（16 kHz 一度超目标 10.8 dB）。
4. **母带留 0.2 dB 余量。** MP3 编解码会让真峰上冲 0.1–0.2 dB；定 −1.0 时解回来是 −0.80，不过。
5. **24-bit WAV 必须补符号位。** Python 标准库 `wave` 读 24-bit 会少读 6 字节；
   不补符号位则 −0.5 读成 +1.5（读回来峰值 228）。
6. **"两次哈希一致"这条断言自己也会骗人。** `verify.py --twice` 重建时没传 `--variant`，
   于是比的是丙 vs 乙两个不同版本——在工作机上因为定稿=默认值，一直是绿的。
   **只在 clone 里才暴露**（这正是"全新 clone"这一步的价值）。

## 五、必须你判断的一件事

**写它的 agent 没有耳朵，没听过这首曲子的任何一个音。**

所有指标只证明"结构对、平衡对、动态对、不糊"，证明不了"动人"。
`docs/04-PROOF.md` §6 列了五条它确实不知道的事：好不好听、音色像不像、和声在听觉上成不成立、
+24.6 dB 的动机突出度是不是过头、整体的电影感。

**所以交件前请听一遍 `out/muxi.mp3`。**
